# Что изменилось: подготовка AmpireVPN к коммерческому запуску

Прежнее название проекта — Celeste | VPN. Сохранена совместимость с уже созданными данными: пользователи в панели под именем
`celeste_<id>` подхватываются, миграции обратно совместимы, том БД прежней версии можно использовать
(`POSTGRES_USER=celeste`, `POSTGRES_DB=celeste` в `.env`).

## Продукт

* **Название AmpireVPN** во всех текстах, платежах, чеках, страницах, метриках, логах, Docker-файлах.
* **Единый стиль «премиум»**: обращение на «вы», короткие строки, маркер ◆, ключевые факты через тире; подписи кнопок — в одном
  словаре `app/bot/labels.py` (без эмодзи, глагол для действия, существительное для раздела). Меню: `Моя подписка · Приглашения · Поддержка`.
* **Первый запуск**: согласие с документами кнопками-ссылками (`Оферта | Конфиденциальность`, `Соглашение | Персональные данные`)
  и кнопка `Подключить`. Нажатие фиксирует акцепт (время + версия документов). Документы (оферта, политика, соглашение,
  согласие на ПДн, условия автопродления и возврата) — ссылки-заглушки, настраиваются в `.env` или в админке.
* **Срок подписки 1 / 3 / 6 / 12 месяцев** (скидки 5/10/20 % — настраиваются; год = 365 дней), экран «Ваш заказ» с разбивкой суммы.
* **Доплата LITE → PREMIUM** считается по суточным ставкам текущих цен, независимо от срока и скидок, никогда не отрицательна,
  не зависит от того, как менялись цены (тесты на 8 наборах цен и на тарифы с разной длиной «месяца»).
* **Устройства**: LITE — 1, PREMIUM — 3, на любом тарифе +25 ₽/мес за устройство (настраивается). Степпер `[−] N [+]` с живой
  ценой, пропорциональная докупка, включение в продление и автопродление, обратное уменьшение лимита, единая точка входа
  «Подключить устройство» (инструкция / увеличить лимит / удалить / перейти на PREMIUM). Доп. устройства сбрасываются вместе с подпиской.
* **Поддержка**: `Поддержка` открывает раздел с `Вопросы и ответы` (Telegraph-заглушка), `Написать в поддержку`, `Документы`.

## Исправления по аудиту

| № | Проблема | Решение |
|---|---|---|
| 1 | Деньги списаны, подписка не продлена | Поиск платежа по `metadata.payment_id`; таймаут/5xx не отменяют автосписание, повтор с тем же ключом идемпотентности; сообщение «не прошло» при неизвестном исходе не отправляется; ежедневная сверка **ЮKassa → БД** (+ кнопка), восстановление недостающих платежей в очередь «На проверке» |
| 2 | HTTP к панели внутри транзакции | `_sync_locked`, `activate_trial`, `revoke_link`: читаем → закрываем транзакцию → панель → короткая запись; `pool_timeout` 5 с, `statement_timeout`, `idle_in_transaction_session_timeout`; `PANEL_CONCURRENCY` 20; AST-тест запрещает сетевые вызовы внутри `ctx.session()` |
| 3 | Бэкап непригоден для прода | PITR (pgBackRest) + копия в S3 вне сервера + шифрование + ежемесячный тест восстановления + алерты свежести; дамп в Telegram — только зашифрованный, без пароля не отправляется; повтор при сбое |
| 4 | Юридический минимум | Документы кнопками, акцепт с версией, условия автопродления и явное согласие **до** привязки карты, уведомление при вводе email, ссылки на оферту и возврат на экране оплаты, экран «Документы» (согласуйте тексты с юристом) |
| 5 | Рассылка медленная | Параллельные отправители (пачки по 25), раздельные бакеты `tg:bc` (рассылка) и `tg:bg` (служебные), общая пауза после flood-control |
| 6 | Мониторинг слеп к воркеру | Prometheus-конфиг скрейпит `api` **и** `worker`, алерты (задача падает/молчит, панель, Redis, needs_review…), сторож в воркере, гистограммы |
| 7 | Несовпадение суммы → вечный спам | Статус `needs_review`, один алерт, ручное «Начислить/Отклонить»; пачка сверки больше не ограничена 300 |
| 8 | Автосписание: потолок и дубли | Постраничная обработка без потолка, повторы D+1/D+3 с льготным доступом, защита от pending-платежа, 401/403 → алерт вместо глобального выключения |
| 9 | Авария панели бьёт по новичкам | Сброс бэкоффа при восстановлении панели (потолок 10 мин), приоритет оплатившим без ссылки, экран «оплата получена — настраиваем доступ» + `Повторить` |
| 10 | Redis — жёсткая зависимость | Fail-open throttle и FSM (`FailOpenStorage`), локальные блокировки, алерт на Redis |
| 11 | Конфигурация и схема | В production запуск останавливается при ошибке миграций, `change-me`, пустых `OWNER_IDS`, пароле БД по умолчанию, http, пустом токене панели, тарифе без сквадов |
| 12 | Антиабьюз | Пробный период: лимит трафика и устройств до первой оплаты; рефералка: возраст ≥ 24 ч, потолок наград, суточный лимит; проверка канала — fail-closed с алертом |
| 13 | Остановка и деплой | `stop_grace_period: 45s`, дренаж фоновых задач и воркера, `rolling-update.sh` по одной реплике |
| 14 | Рефералы грузят панель | `next_check_at` + backoff по возрасту (15 мин → 24 ч), закрытие старых ожидающих |
| 15 | PgBouncer | `prepared_statement_name_func` + отключённый кэш prepared statements |
| 16 | Caddy | Пассивные health-check, `lb_try_duration`, `/healthz` `/readyz` `/metrics` не публикуются, токен метрик только в заголовке, `/readyz` — отдельный пул и кэш, Redis не выводит реплики из ротации |
| + | `compare_digest` с не-ASCII | `safe_eq` на байтах (401/404 вместо 500) |
| + | Возврат двумя админами | Статус-«захват» `refunding` под блокировкой, снятие дней ровно один раз, добивание зависших возвратов |
| + | Напоминания и бэкап помечались «отправлено» без отправки | Отметка только при успехе/блокировке бота; флаг бэкапа — после успешной отправки, повторы |
| + | Рассылка: дубли, пауза, удалённое сообщение | Пачка 25 (≤25 дублей), статус проверяется перед каждой пачкой, удалённый источник → пауза + один алерт |
| + | Notifier без повторов | Повторы при сетевых ошибках, исходящая очередь Redis для «оплата получена» |
| + | Промокод `reserved` | Бронь живёт 7 дней, освобождает место `max_uses` |
| + | cleanup одним DELETE, гонка `ensure_defaults` | Пакетные удаления с паузами; `INSERT … ON CONFLICT DO NOTHING` |
| + | Журнал ошибок одной реплики, метрики без гистограмм, нет user_id | Общий журнал в Redis, гистограммы, `user_id` в каждой строке лога |
| + | Ссылки на Happ захардкожены | Проверка раз в 6 часов, алерт, автоподмена битой ссылки GitHub на страницу релизов |
| + | requirements без пинов, нет CI, нет тестов | Границы версий + `scripts/lock.sh` (lock с хэшами), CI (тесты, миграции на настоящей PostgreSQL, сборка, валидация compose/Caddy/Prometheus/shellcheck), 150+ тестов |
| + | Роли админов | `support`, `billing`, `marketing`, `ops`, `admin`; права по действиям; возвраты/админы/удаление/бэкап — только владельцам |
| + | Баг: «Проверить в ЮKassa» в админке передавал id провайдера в `settle` | Исправлено |
